# 教材形式化任务输入包模板

每个独立任务填写一份；准备、证明实现和成果复核分别建立任务版本。未填信息写“未知/待确认”，不继承上一任务的成功状态。

## 1. 身份与阶段

- 包编号 / 任务 ID / 修订号：
- 本轮阶段：陈述与依赖审阅 / 证明实现 / 成果复核（选择一项）。
- 本轮具体目标与停止条件：
- 所需技能与实际调用记录：
- 用户已确认事项及证据来源：

## 2. 教材与准确命题

- 教材文件标识、SHA-256：
- 章节、公式/结论编号、印刷页、从 1 起的 PDF 页：
- 原页附件及页码对应；未直接读原页时的证据边界：
- 对每个 item_id：自然语言命题、Lean 结论类型、变量/量词、定义域、全部假设、教材原意、表示推广与额外条件。
- 特别核对维数、空索引、质量正性、正则性、解区间；不得把目标藏进假设。

## 3. 源码和环境基准

- 仓库 URL / 分支 / 输入提交：
- 固定 lean-toolchain / mathlib revision / manifest：
- 项目本地声明完整 import 闭包：
- 已证明依赖及其实际状态；未证明依赖清单：
- 本地未提交输入：用包内清单逐项 SHA-256 固定，不依赖远端旧提交。
- 网站实际路径、HEAD、版本或明确的未知项：由返回元数据填写。

## 4. 输入快照

- 文件白名单与用途：
- 包内文件清单：PACKET_MANIFEST.csv；不包含清单自身，避免循环哈希。
- PACKET_METADATA.json 保存输入清单哈希、阶段和基准。
- 归档 SHA-256 单独记录在归档外；生成后文件变动应建立新包，不能覆盖已发版本。
- 排除 .git、.lake、账户目录、凭据和无关材料；教材只附任务所需原页。

## 5. 写入范围

- 可编辑/新增路径：
- 不可修改路径与公共接口：
- 本轮是否授权新证明、网站发送、Git 提交/推送：分别明确。
- 准备阶段只写报告、CSV 和探针文本；未证明声明留在文档，不写带占位的正式 Lean 模块。

## 6. 返回成果

- RETURN_METADATA.json：包 ID、输入清单哈希、实际基准/版本、技能、检查、输出路径/哈希、缺项。
- 陈述/假设审阅；修订差异表；依赖图及精确 API。
- 逐项 ledger：陈述状态、类型检查、证明完成、本地工程验收和语义复核分别记录。
- 原始探针、命令、退出码与完整输出；没有执行就写未运行。
- 证明实现阶段另交完整源码/补丁、关键定理公理依赖及未解目标。

## 7. 验收

- 先检查输入身份与哈希，再复核陈述及原页，再检查实现。
- 正式源码变化时运行项目 scripts/check.ps1，补充关键 #print axioms；不要将类型检查当证明、单文件检查当完整工程验收。
- 禁止 sorry、admit、新项目公理和 unsafe 绕过；标准 Lean 逻辑依赖如实登记。
- 保存原始返回文件；更新映射/假设/状态、当前检查点和日志，按实际结果登记。
