# MathCopilot 与教材形式化工作流分析

核查日期：2026-10-01（Asia/Shanghai）。本轮仅分析并保存建议；没有修改 Lean、工具链、账户配置，没有调用子 agent 或发送外部证明任务。

## 结论与证据边界

MathCopilot 适合承担证明路线探索、依赖分解、局部 Lean 证明和反馈修复，并保留可复核的研究产物。对本工程，建议由本地 Codex 组织教材核对与任务交接，让 MathCopilot 参与证明探索/起草，由本地固定版本工程验收成果。优先改善任务输入、版本一致性和交付证据，然后试行少量子 agent。

本轮读取网站公开首页、中文帮助的总览与完整指南，并核对作者论文及 OpenAI 官方子 agent 文档。指南标注版本 1.1、最后验证 2026-08-04。实际账户的技能安装、并发额度、托管工具链版本没有在本轮认证核查。公开指南展示的 Ramsey 案例为 Lean/mathlib 4.28.0；论文的一个实验为 4.30.0-rc2，均不能推出用户现在任务的运行版本。

工程实际分支为 `chapter01-kinetic-energy-nonneg`，HEAD 为 `6203fc19908312faf9c40d52cb299edb42422973`。已有定义与动能非负性证明，T1–T5 新证明尚未开始。本轮核对的 `STATUS.md` 记载：MathCopilot 已参与定义及证明起草并做托管检查，当时 shell 缺少 lake/pwsh/powershell，托管版本未暴露；随后由本地固定 Lean/mathlib v4.34.0 验收。这是历史证据，本轮未重新运行 Lean 检查。

## 网站功能如何用于本工程

指南列出六个内置流程：`math-brainstorm`、`math-literature`、`lean-blueprint`、`lean-proof`、`qed-simulation`、`math-manuscript`。下表的工程分配为本轮建议，不是网站已完成这些任务的记录。

| 工作 | 可用流程 | 对本工程的具体帮助 | 验收边界 |
| --- | --- | --- | --- |
| 比较证明路线 | Math Brainstorm | T4 比较速度形式与 Hamiltonian 形式的能量守恒证明；T5 梳理球面紧性路线 | 给出适用条件、子引理与 API 风险；不能擅自加强教材假设 |
| 构造依赖地图 | Lean Blueprint | 把 T1–T5 与 Theorem 1.1 拆成定义、桥接引理和主结论 | 文档中的声明与教材逐项对应；节点数量不计作证明进度 |
| 局部完整证明 | Lean Proof | T1 正质量传递、对角矩阵性质；T3 动量与速度能量的代数一致性 | 交付完整源码、依赖和检查证据；本地固定版本通过 |
| 分析证明错误 | Lean-first / NL-first | 对明确目标迭代修复；复杂分析目标先组织自然语言论证，再逐步形式化 | 改动后重新检查；未解目标明确登记 |
| 定理与外部文献调查 | Math Literature 与检索 | 查 ODE 延拓、Lyapunov 稳定性、后续随机分析所需依赖 | 文献内容回原文核对；mathlib 声明回固定版本核对；未检出不等于不存在 |
| 反例与计算实验 | QED Simulation | 排查遗漏条件；后续数值方法的误差、稳定性实验 | 实验指导建模，不能替代一般性 Lean 证明；如 x⁴ 的 Hessian 反例宜再用精确论证确认 |
| 解释与文稿 | Math Manuscript | 整理章节证明说明、假设对照和交付报告 | 只按实际证据写完成状态；与正式库和原页一致 |

指南还提供 NL-only 与 NL-review，它们适合纸笔证明探索和独立审阅；审阅通过不改变 Lean 证明状态。上述功能与入口见[技能说明](https://mathcopilot.cn/help#manual-skills)。

教材逐页排漏、PDF 公式辨认、符号统一可以请网站辅助，但本轮没有验证其对这本 461 页 PDF 的自动完整提取能力。建议按节交给它已经核对的原页和陈述，不把整书上传后的回答当成完整覆盖证据。

## 必须解决的工作流差异

1. **Blueprint 与本工程的占位规则不同。** 官方流程允许生成含 sorry 的草稿骨架，即使骨架通过 Check 也不表示证明完成。本工程 AGENTS 禁止把未证明陈述以占位证明加入正式 Lean 库。默认让网站输出 Markdown 陈述/依赖报告；若采用骨架，使用明确隔离的探索项目或副本，并确保其 AGENTS 允许该草稿流程。只有无占位且本地验收通过的完整结果进入正式库。
2. **连接成功不代表环境与源码同步。** 每次记录网站任务的项目、分支、基准提交、目标源码哈希、完整 import 闭包和实际工具链。本地尚未提交的路线、审计、交接资料不会随 GitHub 旧提交自动出现。输入交接应选取本任务必要文件，并在用户授权外部发送后同步。
3. **托管检查与正式验收分别记账。** 单文件零错误不覆盖全工程，也不能说明假设忠实于教材。正式源码变化后运行 `pwsh -NoProfile -File scripts/check.ps1`；关键结论补充 `#print axioms`。mathlib 标准逻辑公理应按项目标准解读，重点排除 sorryAx 和未经接受的项目新公理，不能简单要求所有定理公理列表为空。
4. **本轮核对的 CI 已存在。** `.github/workflows/lean_action_ci.yml` 已调用 lean-action 和 scripts/check.ps1，无需再建重复 CI。后续重视精确提交的 CI 结果及本地结果。本轮没有查询最新远端 CI。

## 子 agent：区分网站内部与本地团队

作者论文描述 Brainstorm、Blueprint、Prover、Formalizer、Aggregation 五种内部角色。公开指南也说明 Task 的 SubagentPanel 可查看并行角色、摘要和子会话。因此网站已经有 agent 协作相关机制；但本轮公开说明没有建立“用户可任意添加自定义角色、选择并发数或更换各子 agent 模型”的完整配置方法，不能承诺在账户内存在这些开关。

本地 Codex 可以作为直接可试行的协作层。当前会话已经提供子 agent 工具，最多主 agent 加三个活动子 agent；本轮分析没有调用它们。未来明确要求委派独立任务即可先使用，暂不必安装额外编排框架。OpenAI 官方文档也支持项目级 `.codex/agents/*.toml` 自定义角色，但此类配置应按实际客户端版本核对，不能把本地设置当成 MathCopilot 服务器设置。

建议初始组织如下（不要求每轮全部运行）：

| 角色 | 任务 | 交付 | 写入范围 |
| --- | --- | --- | --- |
| 主 agent | 固定公共定义和声明，组织网站任务，集成成果并运行正式检查 | 最终源码、验收记录、交接状态 | 正式模块与共用交接文件由它统一维护 |
| 教材审阅子 agent | 对照原页，审阅维数、索引、质量、正则性和量词 | 页码、条件对照、歧义与反例 | 默认只读源码；独立审阅报告 |
| API 子 agent | 检索本地固定 mathlib；做最小类型和实例化检查 | 精确声明、import、可执行小例子、失败记录 | 专用临时文件或独立副本；避免争写 Scratch.lean |
| 独立审阅子 agent | 审阅完成后的 Lean statement 和证明依赖 | 结论是否弱化、条件是否隐藏、依赖是否未证明 | 默认只读；最终关键语义仍由负责人复核 |

MathCopilot 承担证明探索/起草，与这些本地角色协作。任务仅在公共声明和接口稳定后并行。并行写代码时分配不同文件或 worktree；共享工作区的子 agent 不自动获得独立 checkout。主 agent 统一改顶层导入并运行全工程构建，避免多人同时覆盖文件或反复全量构建。

T1→T2/T3→T4 等依赖链不能因增加 agent 消失；并行较适合原页审阅、API 核对、互不依赖的辅助引理及独立复核。增加并行通常增加 token 用量，收益需实际测量。

## 建议按收益顺序补齐

### 第一优先：任务输入与阶段验收

先确认所需内置 Skill 已启用且安装到当前网站项目；技能可见、GitHub 连接和实际技能可用是不同状态。路线比较→陈述/依赖→局部证明→验证逐段交付。同一条依赖链按阶段推进；独立核查任务可以并行。

每个任务包至少包括：任务 ID 与原页、准确自然语言命题、变量和量词、全部假设、Lean 类型与目标声明、固定版本、基准提交/源码、已证明依赖、允许编辑文件、验收命令。网站返回源码或补丁、自然语言证明、Proof Report、真实版本与检查范围、未完成项和失败原因。若无法取得工具链版本，明确写未知。

建立可复用的教材陈述审阅/成果验收流程很有价值：把这些字段与当前 AGENTS、FORMALIZATION_MAP、ASSUMPTIONS 连接起来，而不是追加更多泛泛“数学专家”提示词。网站支持自定义 Skill 导入；本轮仅建议，未创建或安装 Skill。

### 第二优先：T1 上试行两个独立子 agent

并行核对教材与 API，主 agent 整理一致陈述，再交给 MathCopilot 做小目标。完整证明返回后进行独立审阅、固定版本检查和记录。先测一批，再决定是否维持第三个审阅角色。

衡量每个“本地通过且语义已复核”引理的总耗时、token、版本/API 返工次数、陈述修改次数和未解依赖。任务数量、聊天长度、蓝图节点和模型自报完成率不是效率指标。不预先承诺几倍加速。

### 第三优先：按实际瓶颈加工具与知识库

- 自定义 Lean 库的索引要核对仓库 HEAD；新增本地引理后按需更新，让网站复用已接受成果。
- 若现有 Lean 连接不能读当前目标、诊断、完整声明和定义位置，再补相应接口；若已有这些能力，优先修好使用方式和版本对齐。
- 后续需要大量外部论文时再连接 Zotero Web 文献库并建立索引。官网指南支持该工作流，但连接成功不等于索引已就绪。当前 T1/T3 不依赖新增文献库。
- 复杂证明探索可试较高推理强度；机械整理可维持普通设置。以本工程任务的实际结果选择，不依论文小样本排名直接更换全部模型或升级 Lean/mathlib。

## 补充：如何核对三个技能已安装

在 MathCopilot 首页打开“技能库”（Skill Hub），分别查找 Math Brainstorm / math-brainstorm、Lean Blueprint / lean-blueprint、Lean Proof / lean-proof。核对 Enabled 已开启，再进入各项“管理”确认教材对应的网站项目已安装；已满足条件无需重复安装。已安装项目总数不能说明某个指定项目在其中。注意指南说明 Enabled 会遍历账户现有项目启停，而“管理”用于指定项目的安装/卸载。

设置完成后重新打开详情检查持久状态，回到目标项目的新 Task，从输入区“+ → 技能”核对三项可供选择。技能在任务启动时提供给模型，不能仅用已经运行的旧 Task 判断新设置是否生效。此步骤可停在菜单核对，不必为确认配置发送教材证明任务。本补充依据重新读取的[官网技能指南](https://mathcopilot.cn/help#manual-skills)，没有核查或修改用户账号的实际设置。
